# T5-base text conditioner

Both models this repo targets condition on the same text encoder. audiocraft's
`T5Conditioner` (`audiocraft/modules/conditioners.py`) is configured with
`name: t5-base` in both `facebook/melodyflow-t24-30secs` and every `thepatch/*` MusicGen
finetune, and `t5-base` is plain google-t5 v1.0: **ungated ReLU** feed-forward, learned
relative position bias, bias-free RMS norms, 32128-entry SentencePiece Unigram vocab.

That is exactly the model `sa3.cpp` already implements for stable-audio-tools, so
`src/ac/t5.h` and `src/ac/tokenizer.h` are ports of `sa3.cpp`'s `src/sat/t5.h` and
`src/sat/tokenizer.h` with the metadata namespace changed (`sat.*` → `ac.*`).

## One real difference from stable-audio-tools

stable-audio-tools pads every prompt to a fixed length (64 or 128). **audiocraft does
not** — `T5Conditioner.tokenize` calls the tokenizer with `padding=True`, which pads to
the longest entry *in the batch*. So `ac.t5.max_length` in the GGUF is a **capacity bound
for graph sizing, not a pad length**, and `ac-textenc` encodes each prompt at its own
token count by default.

This is safe: the encoder is bidirectional and padded keys receive an additive `-inf`
mask, so hidden states at valid positions do not depend on how much padding follows.
Measured below.

Where the padding *does* matter is downstream, and differently for each model:

- **MusicGen** passes **no cross-attention mask at all**. `T5Conditioner.forward` zeroes
  padded positions after `output_proj` (bias included) and `ConditionFuser` forwards the
  tensor as-is, so padded positions are attended over as zero vectors. With CFG the null
  branch is an all-zero context of the *same* length as the conditional one, because
  `""` tokenizes to a single `</s>` and is then padded to the real prompt's length and
  fully masked to zero.
- **MelodyFlow** passes `log(mask)` as `cross_attention_mask`, i.e. a genuine `-inf`
  mask, so padding is truly ignored and the context length is irrelevant.

## Conversion

```bash
T5=~/.cache/huggingface/hub/models--t5-base/snapshots/a9723ea7f1b39c1eae772870f3b547bf6ef7e6c1
.venv/Scripts/python.exe tools/convert_t5.py \
  --src "$T5/model.safetensors" --config "$T5/config.json" --tokenizer "$T5/tokenizer.json" \
  --out models/t5-base-encoder-0.1B-v1.0-F16.gguf --out-type f16
```

99 tensors, 109,628,544 parameters, 32100 tokens. The encoder weights and the tokenizer
live in one file; `ac::UnigramTokenizer::load()` and `ac::load_gguf()` both read it.

The converter rejects a gated feed-forward config, so `google/t5-v1_1-base` and the
`flan-t5` family fail loudly rather than converting into a silently wrong encoder.

## Measured parity

Reference: `tools/dump_t5_refs.py`, which runs `T5EncoderModel.from_pretrained("t5-base")`
in float32 and applies the same post-hoc zeroing of padded positions the conditioner does.
Prompt `"80s pop track with bassy drums and synth"` (12 tokens including `</s>`), CPU.

| build | vs torch cossim | max abs err |
|---|---:|---:|
| F32, no padding | 1.000000000 | 6.6e-07 |
| F32, padded to 64 with mask | 1.000000000 | 7.2e-07 |
| F16, no padding | 0.999999934 | 4.4e-04 |
| F16, padded to 64 with mask | 0.999999926 | 5.1e-04 |

F32 reaches float32 round-off, so the graph is exact and the entire F16 delta is weight
quantization. F32 padded-vs-unpadded differs by 3.3e-07, which confirms the mask path:
padding changes nothing but accumulation order.

Tokenizer output matches `T5Tokenizer.from_pretrained("t5-base")` exactly on ASCII and
punctuated prompts, including a full 28-token terry preset. The known gap inherited from
`sa3.cpp` is the tokenizer's precompiled Unicode normalization table, which is not
implemented; ordinary ASCII/UTF-8 prompt text is unaffected.

## Reproducing

```bash
# reference (needs torch + transformers; any gary4local service venv has them)
.../services/melodyflow/env/Scripts/python.exe tools/dump_t5_refs.py \
  --prompt "80s pop track with bassy drums and synth" --out refdata

# ours
build/bin/Release/ac-textenc --t5 models/t5-base-encoder-0.1B-v1.0-F16.gguf \
  --prompt "80s pop track with bassy drums and synth" --out cppout/t5_hidden.f32

.venv/Scripts/python.exe tools/cossim.py --ref refdata --cpp cppout
```

`--taps` on the dumper writes each encoder block's output as `t5_block<N>.npy` for
bisecting a divergence.
